# Phase 3 report: wallet sign-in and role-based access (API)

Implements section 2 of [ADR 0019](../decisions/0019-phase-3-scope-and-demo-issuers.md) outside the contract: operators sign in with a NEP-413 wallet message and the admin endpoints check the roles the contract reports. Branch `feat/nep413-auth`. The contract side (`get_account_roles`, the new roles, the signer key registry) is another branch; this one calls the view and fakes it in tests. The web app is untouched.

## Decisions

- **Order in `verify`.** The signature is checked first, then the key over RPC and the roles, and only then the nonce is spent (one atomic `UPDATE ... WHERE consumed_at IS NULL AND expires_at > now`). ADR 0019 lists "consumes the nonce" before the RPC check; the order here keeps an RPC outage from burning a challenge, and two concurrent verifies of one challenge still yield exactly one session. A refused signature or key does not spend the nonce either, which costs nothing: the nonce is useless without a signature for it.
- **Key ownership.** The key must exist on the account (`view_access_key`, finality `final`). A function-call key is accepted (NEP-413 asks for full access, but a function-call key still proves the account issued it) and recorded: `auth_sessions.key_type`, the verify response and the audit detail. Nothing else about the key is stored.
- **Callback URL.** NEP-413 includes `callbackUrl` in the signed payload and browser wallets default it to the page URL, so `verify` takes an optional `callbackUrl` and rebuilds the payload with it.
- **Sessions slide.** There is no renew endpoint: each authenticated request moves the expiry to `min(now + 15 min, sign-in + 8 h)`. Revocation is immediate (`revoked_at`); expired and ended rows are swept on the next challenge.
- **Roles.** Stored on the session with the time they were read; re-read when older than 60 seconds or when the policy entry is `sensitive`. A failed chain read fails the request (500), never serves the cache. Unknown role names from a newer contract are dropped.
- **Policy table.** `src/auth/policy.ts` maps each admin operation to roles, `sensitive` and its audit action. Reconciliation and admin metrics: any of owner, registrar, compat_approver, pauser (the attester roles sign attestations and see no operator data). The reconciliation read is `sensitive` (it names flagged quotes and vault readings, and a revoked role should stop at once); the metrics are cached. `/metrics` has the same roles but a scraper needs the break-glass key because a session idles out. A test fails if an `Admin`-tagged endpoint has no policy.
- **Break-glass.** `ADMIN_API_KEY` passes every policy and is audited as `legacy-admin-key` with a fingerprint of the key in `detail`. This changes the old audit label (`admin:<fingerprint>`), so `admin-audit.test.ts` and `metrics-endpoints.test.ts` were updated; the old test pinned the fingerprint actor. It is no session (`/v1/auth/me` refuses it).
- **Audit.** `actor` is the account, `actor_key` the access key (new nullable column), `detail` the extras. New actions: `auth.sign_in`, `auth.sign_in_failed` (anonymous actor, reason in `detail`, never the signature), `auth.logout`, `admin.forbidden`.
- **NEP-413 lives in `quote-engine`**, next to the keys and base58 it needs, so `apps/api`, `scripts` and the e2e share one implementation without a new workspace dependency (which would change the lockfile).
- **Recipient** defaults to `pontis-api.<network>`, so a signature for the sandbox is not a sign-in for Testnet.
- **`ROLE_NAMES`** is in `packages/api-types` and holds the names the contract agent was told to return; if the contract names differ, fix them there.
- **Rate limit.** `challenge` and `verify` are in the admin class with their own counter, so a dashboard polling admin reads cannot lock an operator out of signing in.

## Verification

`tsc --noEmit` and `eslint` are clean in domain, api-types, db, near-client, quote-engine, scripts, `tests/e2e`, `apps/api` and `apps/indexer`; `prettier --check .` is clean. vitest passes in each, run alone (domain 56, api-types 80, near-client 71, quote-engine 90, scripts 108, `apps/api` 300, `apps/indexer` 77 tests; Postgres on `localhost:5439`). `apps/api` covers the sign-in flow with a fake wallet and a fake chain: nonce single use, expiry at the 5 minute edge, concurrent verifies, wrong key or account or callback URL, a key missing from the account (nonce kept), function-call keys, token hashing, sliding and capped sessions, logout, role caching and the sensitive re-read, 403 and 401, the break-glass key, and the sign-in rate limit.

Not run: the sandbox end-to-end scenarios (they need the Rust build and a contract with `get_account_roles`), the `tests/e2e` `auth` scenario, and `auth-login` against a real chain. The fake wallet in the tests signs with the same `signNep413` that the vector test pins to an independent Python computation; no real wallet (MyNearWallet, Meteor, Ledger) was exercised, so how each one fills `callbackUrl` and encodes the signature is untested.

## Not done

- The contract view `get_account_roles` is another agent's change; until it lands, sign-in against a real deployment fails at the roles read (the e2e `auth` scenario will fail the same way).
- No session list, no "log out everywhere" endpoint, no binding of a session to a device.
- The `/metrics` scraper still uses the break-glass key; a long-lived scoped scrape token would remove that and was not asked for.
- The legacy key is removed in phase 7 (ADR 0019), not here.
