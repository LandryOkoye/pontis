# What is deliberately mocked or simplified in the MVP

Phase 0 deliverable (brief §18.3): an explicit list of what the testnet MVP fakes, simplifies or leaves out, so nobody mistakes a demo shortcut for a production feature.

| Area                    | What the MVP does                                                                                                                                                                                                                                                                                       | What production would need                                                                  |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| Underlying asset        | `SYN-GOLD-OZ` is a fictional, unbacked claim ([dossier](../asset-dossiers/SYN-GOLD-OZ.md))                                                                                                                                                                                                              | A real, legally defined claim                                                               |
| Issuers                 | Two fictional issuers, both operated by the project                                                                                                                                                                                                                                                     | Real issuers, issuer-controlled contracts, adapters                                         |
| Custody and backing     | None                                                                                                                                                                                                                                                                                                    | Custodian, attestations, redemption path                                                    |
| Evidence                | Self-attested dossiers (`issuer_provided`, `unverified`)                                                                                                                                                                                                                                                | Third-party and independent verification with scope, reviewer and date                      |
| Compatibility review    | One relationship, approved by the project operator                                                                                                                                                                                                                                                      | Documented review against brief §6.6 by a designated authority, separated proposer/approver |
| Eligibility             | On-chain allowlist, not KYC                                                                                                                                                                                                                                                                             | KYC/KYB, sanctions, jurisdiction and lockup checks via issuer adapters                      |
| Pricing                 | Fixed approved unit ratio plus a flat fee                                                                                                                                                                                                                                                               | Market pricing, spreads and slippage for exchange; imbalance fees if any                    |
| Market data (expansion) | Prices, NAV, supply and most trade flow are written by `apps/simulator`, flagged `simulated: true`; only `pontis_trades` rows are real testnet activity                                                                                                                                                 | A real price feed per asset, reserve-backed supply, real trade flow                         |
| Price attestations      | The simulator signs every price with a key derived from a public label (`@pontis/dev-keys`); `submit_price` verifies the signature against a registered key, but the key is public                                                                                                                      | Independent publishers with threshold signing or a real feed, KMS-held keys (phase 7)       |
| Liquidity               | Owner-funded vault, manual replenishment                                                                                                                                                                                                                                                                | Liquidity providers, solvers, inventory management                                          |
| Token supply            | Owner `mint` and testnet `faucet_mint`                                                                                                                                                                                                                                                                  | Issuer-controlled issuance tied to backing                                                  |
| Quote signing           | One ed25519 key in an env var                                                                                                                                                                                                                                                                           | HSM or KMS, key rotation procedure, monitoring                                              |
| Admin control           | Operator holds all roles; deploy key retained                                                                                                                                                                                                                                                           | Multisig owner, distinct role holders, locked keys                                          |
| Contract upgrades       | Redeploy, no migration                                                                                                                                                                                                                                                                                  | Reviewed upgrade path                                                                       |
| Chain data trust        | The indexer reads receipt logs from an RPC node's light-client proof without verifying it                                                                                                                                                                                                               | Independent proof verification (block headers, Merkle paths) or a trusted-node arrangement  |
| Replay and history size | Used quote nonces and all history are kept forever; no pruning                                                                                                                                                                                                                                          | A designed retention scheme (for example nonce windows tied to quote expiry)                |
| Evidence and issuers    | URIs, hashes, provenance labels and issuer lists are recorded, not authenticated                                                                                                                                                                                                                        | Signed attestations, account-control proof, evidence checked by a non-issuer                |
| Network                 | NEAR Testnet only                                                                                                                                                                                                                                                                                       | Mainnet deployment after audit and legal review                                             |
| Chain scope             | Same chain, same contract                                                                                                                                                                                                                                                                               | Bridges, Chain Signatures, proof-verified settlement (deferred)                             |
| Intents, solvers        | Not integrated                                                                                                                                                                                                                                                                                          | NEAR Intents routes, multi-solver quoting (deferred)                                        |
| Confidential execution  | Not built                                                                                                                                                                                                                                                                                               | Supported confidential route, key custody, disclosure model (deferred)                      |
| Agents / MCP            | Not built                                                                                                                                                                                                                                                                                               | Read-only tools first, then constrained write tools (deferred)                              |
| User authentication     | Users: none; the wallet signature on the transfer is the authority. Operators: a NEP-413 wallet sign-in gives a session whose roles are read from the contract ([ADR 0019](../decisions/0019-phase-3-scope-and-demo-issuers.md)); the shared `ADMIN_API_KEY` stays as audited break-glass until phase 7 | Session or wallet-based auth for private data; no shared key; step-up for sensitive actions |
| Monitoring and alerting | Reconciler endpoint and runbooks                                                                                                                                                                                                                                                                        | Alerting, on-call owner, incident process                                                   |
| Backups                 | Local Postgres, no tested restore                                                                                                                                                                                                                                                                       | Backup and restore drills                                                                   |
| External audit          | None                                                                                                                                                                                                                                                                                                    | Independent audit before real assets                                                        |
| Legal                   | None; testnet and synthetic only                                                                                                                                                                                                                                                                        | Jurisdiction- and asset-specific legal review                                               |
| Corporate actions, NAV  | Registrar-entered actions; NAV strikes signed by the simulator key, labelled `simulated`                                                                                                                                                                                                                | Verified action feeds, fund-administrator-signed NAV, issuer-applied events                 |

## Custody, reserves and redemption (phase 4 API)

The machinery is real contract logic; the parties and the numbers are fiction. Every row is labelled `simulated` in the API.

| Area                               | What the API shows                                                                                                                                                                                                                                                                     | What production would need                                                                                                 |
| ---------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| Custodian                          | A registrar-entered record with a test key (`synthetic: true`, never above what the registrar recorded). The simulated custodian signs reserve figures with a dev key                                                                                                                  | A real custodian, legal agreements, a signing key under its own control                                                    |
| Reserve figures                    | Signed numbers a simulator makes up, with `source: "simulated_custodian"`. The report URI and hash point at nothing the API fetches or checks                                                                                                                                          | A report the custodian publishes, checked by an independent attester                                                       |
| Redemption                         | The state machine and the escrow are real; the issuer back-office is a test account. Fee and net are figures the simulator honours off-chain; no value moves                                                                                                                           | Fiat or custody settlement, KYC on the payout, a legal redemption right                                                    |
| Issuer reliability                 | Counters kept by the contract, a score derived from them, labelled `simulated_issuer`                                                                                                                                                                                                  | Real issuer track record over time, disputes, third-party review                                                           |
| Reserve relayer                    | A dedicated testnet account (`PONTIS_RELAYER_*`) that pays for relayed attestations; no custodian or user key                                                                                                                                                                          | A funded, monitored relayer or the custodian submitting directly                                                           |
| Reserve attestations and custodian | One fictional custodian whose reserve attestations are signed by `scripts/reserves.ts publish` with the dev `reserve-attester` key (public label), tracking the token's real supply at a configurable cover ratio so a demo can drift it on purpose; every figure is `simulated: true` | Independent custodians and attesters with KMS-held keys, audited reports, a real custody relationship (phase 7 and beyond) |
| Issuer back-office                 | `scripts/backoffice.ts` accepts and fulfils redemptions after a delay with a dev key and can be told to ignore one so it expires; its receipts are synthetic strings; no value moves                                                                                                   | A real issuer operation, payout rails and evidence                                                                         |
| Reserve monitor                    | The indexer calls `refresh_supply` and `evaluate_reserve` once a minute with a testnet account whose key is an environment variable                                                                                                                                                    | A monitored, redundant job with managed keys and alerting                                                                  |
| Payout instruction                 | The client encrypts it and the API stores the ciphertext unread, hashing it for the `redeem:` message; no endpoint returns it and nothing decrypts it. A redemption pays nothing, so there is nothing to pay to                                                                        | A key custody scheme, an issuer who can decrypt it, payout rails and retention rules                                       |
| Issuer login                       | An account listed in an issuer's `controlled_accounts` may read the queue and get unsigned accept, reject, fulfil and mint actions, checked against the chain on every call. Listing is a registrar's unproven claim                                                                   | Proven account control, an issuer portal with its own review and separation of duties                                      |

## Demo custody data (seed-custody)

Fiction written through the real contract methods; every row is `simulated`.

| Area               | What the seed does                                                                                                                                                                                | What production would need                                            |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| Custodians         | Eight invented names (vaulted metals, fund and note custody, an on-chain vault, an SPV registry, carbon, stable-value) registered `synthetic: true`, `unverified`, no evidence                    | Real custodians, agreements, evidence an independent attester checked |
| Reserve stories    | A policy and one simulated attestation per linked token: healthy, thin, breached, warn-only, `pause_mint`, a lapsing one and one never attested. The cover ratio is a number the data chose       | Independently attested reports of assets that exist                   |
| Decay              | The lapsing story is a 5 minute max age with no refresh; the others need `reserves publish --loop` (skipping that one and the never-attested token) once a day has passed                         | Monitored publishers, alerting and a repair procedure                 |
| Redemption terms   | Fictional minimums, maximums, fees, windows (including one gated note) and settlement days, set by the registrar and enforced by the contract                                                     | Legal redemption rights and a payout operation                        |
| Seeded redemptions | Three requests left `requested`, `accepted` and `fulfilled`; the deployer is the holder and the issuer's token account (the deployer's key) accepts and fulfils; the burn is real, no value moves | Real holders, a real issuer back office, fiat or custody settlement   |
| Gated tokens       | `pontis-core` is made the minter of two tokens so a redemption can burn and a mint can be gated; the owner mint and faucet close there                                                            | The same gate, with the minter set once by a governed owner           |

## Demo catalogue (seed-catalogue, seed-profiles)

The catalogue adds fiction on top of the MVP seed. Each row is a label or a story, not behaviour.

| Area                              | What the catalogue does                                                                                                                                                                                                                                                                                                                                    | What production would need                                                                                             |
| --------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| Assets                            | Six more fictional claims (`syn-acme`, `syn-ustb`, `syn-villa`, `syn-credit`, `syn-usd`, `syn-nova`) with eight owner-minted tokens. A stock split, a maturity date, a redemption term and an appraisal are text in the [dossiers](../asset-dossiers/README.md); no contract implements them                                                               | Real instruments with legal terms; corporate-action, lifecycle and redemption logic                                    |
| Issuer trust                      | Four fictional issuers shown as `active` + `issuer_attested`, `restricted` + `unverified`, `deprecated` + `issuer_attested`, `rejected` + `unverified`. Each is a status a registrar set and a label; nothing was reviewed, attested or verified, and nothing is `third_party_attested`                                                                    | Authenticated onboarding, attester roles, attestation expiry, a review workflow                                        |
| Lapsed attestation                | `orchard-trust` is `deprecated` and its dossier says an attestation lapsed. The registry has no attestation expiry; the story is not enforced by anything                                                                                                                                                                                                  | An expiry that downgrades or suspends a record, with a signed attestation                                              |
| Relationships                     | `tustb-h` / `tustb-o` is approved by the operator; `tacme-h` / `tacme-m` is only proposed because `tacme-m` cannot be activated under a restricted issuer                                                                                                                                                                                                  | Reviewed relationships between tokens whose issuers are active                                                         |
| Vault inventory                   | Owner-funded for the two tokens of the approved pair only (500,000 whole tokens each); the deprecated issuer's side cannot convert                                                                                                                                                                                                                         | Liquidity providers and inventory management                                                                           |
| Profiles                          | Off-chain `asset_profiles` with `source: "simulated_feed"`, `simulated: true`; `convertible` and `bridgeable` are hints, and a `planned` EVM chain entry marks assets meant to be bridged later. No bridge exists                                                                                                                                          | Issuer-supplied, checked documents; a real bridge for the `planned` entries (workstream F)                             |
| Scale and realism                 | Up to 19 invented issuers (15 more than phase 1, in 15 jurisdictions), 33 claims and 53 tokens in three tiers (`mvp`, `demo`, `full`); names, domains (`.example`) and tickers are invented and checked against a denylist of real brands. Jurisdictions and regulator categories are real places used as plain facts; no issuer is licensed or supervised | Real issuers onboarded through attested applications, real instruments and legal review                                |
| Issuer stories                    | Restricted after activity (`kittiwake-cayman-partners`), lapsed attestation (`wattlebird-capital`, `orchard-trust`), a pending applicant (`peninsula-orient-assets`, `meridian-assets`), rejected before issuing (`baobab-coast-finance`, `vantage-credit`). Each is a status a registrar set                                                              | An attestation expiry that downgrades records, a review workflow, supervised onboarding                                |
| Pairs and guards                  | Approved pairs carry a guard preset sized for the simulated feed; one pair is rejected, others proposed or `ECONOMICALLY_SIMILAR`. The operator is the only reviewer                                                                                                                                                                                       | Reviewed pairs, guards tuned to real price data and real liquidity                                                     |
| Delisting, split, redemption gate | A delisted share is one wrapper moved to `deprecated`; a stock split exists only in a dossier; a redemption gate and two maturities are text                                                                                                                                                                                                               | Two-account delisting under supervision, corporate-action feeds, redemption exits (phase 4)                            |
| Seed cost and size                | `--catalogue=mvp\|demo\|full`; the deploy funds one token account per representation (about 2.80 NEAR each on the slim build) and the seed tops up the core account for registry state                                                                                                                                                                     | A deployment pipeline with real budgets, batching and monitoring                                                       |
| End-to-end custody run            | The `custody` scenario of `tests/e2e` plays the custodian with the public dev reserve-attester key and the issuer back-office with the deployer key of the demo issuer's token account; the accept deadline is 25 seconds so it expires inside a run                                                                                                       | Real custodians and issuers, and a fulfil deadline exercised on a live chain (it is days, so only unit tests cover it) |

See also [ADR 0010](../decisions/0010-deferred-scope.md) for the deferred features and [the threat model](../threat-model/mvp.md) for accepted limitations.
